# 多桶聚合控制台（bucket_console）

> 多桶合一 · 托盘 + 全操控界面：**一眼看桶状态，点按钮做完所有连接管理**。
> 只读数据 + 调度命令 —— 本工具不实现任何认证/协议逻辑，所有动作都执行**你自己配置的命令**。
>
> 两个窗口：**简单界面**（默认，日常用）+ **高级界面**（完整控制台）。简单界面右上角「高级界面」
> 按钮直接弹出高级窗口（同进程，不另起实例、不重复写心跳）。

本目录是作者内部测试版控制台的**脱敏开源重写**：界面结构、交互方式、按钮语义、生命周期模型完全一致，
但所有环境相关的东西（真实标识、路径、脚本名、服务商/品牌）都抽成了配置文件里的占位符。

```
tools/bucket_console/
├── bucket_console.py     主程序（托盘 + 窗口 + 全操控面）
├── console_config.py     配置模型（归一化 / 占位符 / 自检）
├── credstore.py          凭据库（DPAPI / 钥匙串 / 文件降级）+ CLI
├── probe_buckets.py      参考「状态生产端」（204 探测 → 状态 JSON）
├── config.example.json   配置模板（复制为 config.private.json 后填值）
└── README.md             本文件
```

## 1. 快速开始（约 5 分钟）

```bash
# 0) 依赖：tkinter 随 Python 自带；托盘可选（缺了自动降级为纯窗口，功能不减）
pip install pystray pillow            # 可选

# 1) 复制模板（*.private.* 已被 .gitignore 忽略，不会误提交）
cp config.example.json config.private.json

# 2) 填三处必填项（其余可留空，界面会显示「未配置」并提示）
#    probe.target              一个会返回 204 的探活地址
#    buckets[].probe.*         每个桶怎么探测（local / socks / ssh）
#    actions.refresh_state     状态生产端命令（可直接用 probe_buckets.py）

# 3) 先自检，再开界面
python bucket_console.py --config config.private.json --check
python bucket_console.py --config config.private.json
```

其它入口：

| 命令 | 作用 |
|---|---|
| `python bucket_console.py` | **简单界面**（默认）：各桶状态 + 刷新 + 桶服务总开关 + VPN 开关 |
| `python bucket_console.py --advanced` | 直接打开**高级界面**（完整控制台） |
| `python bucket_console.py --check` | 只做配置自检（列出未配置项与填写提示），不开界面 |
| `python bucket_console.py --selftest` | 构造全部界面后立刻退出（冒烟，不闪窗口） |
| `python bucket_console.py --no-tray` | 不启用托盘（纯窗口） |
| `python probe_buckets.py -c config.private.json` | 跑一轮探测，写状态文件 |
| `python probe_buckets.py -c config.private.json --only A` | 只探某个桶 |
| `python credstore.py backend / list / set / get / remove` | 凭据库维护 |

### 1.1 简单界面（默认）

| 区域 | 内容 |
|---|---|
| 顶栏 | 标题 · 数据新鲜度 · **高级界面**按钮 |
| 各桶状态 | 桶 / 状态（按状态着色）/ 说明；**列表高度可拖拽调节**（拖中间的分隔条），默认约 7 行 |
| 桶服务 | 状态（运行中·在线桶 n/N / 已停止）+ **开启桶服务 / 关闭桶服务**（整条链总开关，走 `actions.boot_chain` / `stop_chain`） |
| VPN 代理 | 状态（已开启·规则 / 已关闭·直连）+ **开启代理 / 关闭代理**；**只有填了节点源地址才可用** |
| 底部 | 刷新 · 自动刷新（15/30/60/停）· 退出(全链停) |

窗口默认高度约为高级界面的 60%；拖拽分隔条时下方的控制区会被夹住，永远不会被挤出窗口。

### 每桶快捷操作（⑤运维总控 → ①）

| 按钮 | 行为 | 纪律 |
|---|---|---|
| 详情 | 该桶原始 JSON（白名单 / 在线会话 / 克隆判定） | 只读 |
| 204探测 | 按桶出口探活 3 次（识别门户劫持） | 只读 |
| 刷新真机 | 跑 `actions.refresh_portal` 并展示该桶真机判定 | 只读 |
| 续连/恢复 | `ssh_ifup`（可带真机闸）或自定义 `renew_bucket` 命令 | 闸/二次确认 |
| 单桶测速 | 跑 `actions.speedtest`，用 `{leg}` 传入该桶腿名 | 只读（有流量） |

### 「真机闸」语义（原 F3 刹车）

克隆桶（`kind: "clone"` + `renew.gate: true`）续连前，**必须**先刷新门户判定：

- 目标真机**在线** → 拦截（避免互顶）；
- 判定**未知**（没有该账号的专属凭据 / 接口无可见性） → 也拦截；
- 仅当判定为**离线** → 通过，且仍然二次确认。

## 3. 配置说明

完整字段见 `config.example.json`（每个段落都有 `_note`）。要点：

| 段落 | 作用 |
|---|---|
| `app` | 数据目录与四个文件（状态 / 门户 / 事件 / 测速） |
| `ui` | 标题、托盘名、刷新间隔、走势采样数、窗口尺寸、等宽字体 |
| `lifecycle` | 心跳文件、启动拉起动作、退出全链停动作、退出确认文案 |
| `probe` | 探活地址、curl 可执行名、门户劫持的响应体标记 |
| `aggregation` | 聚合出口的 REST 控制面（可选）：`api` / `group` / `provider` / `direct_members` / 模式文件 / 重启动作 |
| `portal` | 门户产物与凭据文件约定（全局凭据、每账号凭据、属主字段） |
| `vm` | 可选的虚拟路由（承载克隆腿）；`enabled: false` 时该区块不显示 |
| `buckets[]` | 每个桶 = 一条独立会话出口：探测方式、续连方式、账号、腿名、克隆关系 |
| `actions{}` | 所有按钮背后的命令 |
| `tasks[]` | 计划任务清单（Windows 用 schtasks；其它平台显示「不适用」） |

### 3.1 桶的探测方式 `probe.mode`

| 值 | 行为 | 适用 |
|---|---|---|
| `local` | 本机直接 curl 探活 | 本机有线 / 本机无线 |
| `socks` | `curl -x <socks>` 经 SOCKS 出口探活 | 路由器/旁路设备上的第二会话 |
| `ssh` | `ssh <host> curl --interface <iface> ...` | 远端接口（如路由器 ethX） |
| `none` | 不探测（保留上次状态） | 只看状态、不做探测的桶 |

### 3.2 桶的续连方式 `renew.mode`

| 值 | 行为 |
|---|---|
| `ssh_ifup` | `ssh <host> ifup <wan>`，再回读接口 IP（可配 `gate` 真机闸） |
| `command` | 执行 `actions.renew_bucket`，可用 `{wan} {iface} {bucket}` 占位符 |
| `none` | 提示「该桶无需手动续连」（可写 `renew.hint` 自定义说明） |

### 3.3 动作命令里的占位符

`{config}` `{data_dir}` `{bucket}` `{account}` `{mac}` `{leg}` `{iface}` `{wan}` `{target}`

`argv` 用列表（推荐，不经 shell）；也可以写字符串（走 shell）。
任何动作为 `null` / 留空 / 仍是 `<占位符>` → 按钮会提示「未配置」，不会报错。

### 3.4 「配置」页：不改 JSON 也能调参数

高级界面「连接管理 / 工具」里的 **配置** 按钮打开一个 schema 驱动的编辑器，覆盖
`app` / `ui` / `probe` / `aggregation` / `portal` / `vm` 的**标量键**（含布尔开关）。

- **留空 / 仍是 `<占位符>` 的字段 = 不修改该项**（不会把占位符写进配置，也不强迫你填满）；
- 保存前逐项校验（`int` 必须数字、`url` 必须 http(s)），校验失败**不写盘**；
- 保存流程：`*.bak-<时间戳>` 备份 → 原子替换 → **就地热更新内存配置**（窗口标题/探活/控制面等立即生效）；
- 数据目录、凭据路径、窗口尺寸、刷新间隔属于「已初始化」项，**重启控制台后生效**（保存提示会写明）；
- 桶请到「桶管理」页编辑；`actions`（命令清单）结构较复杂，仍建议直接改配置文件。

> `python tools/bucket_console/checks/verify_ports.py` 会验证该对话框的保存 / 备份 / 校验 / 热更新行为。

### 3.5 界面状态持久化

窗口几何、刷新间隔、当前标签页会记到 `app.data_dir/ui_state.json`（原子写），下次启动自动还原。
删除该文件即恢复默认布局。

### 3.6 「桶管理」页：增 / 删 / 改 / 排序 + MAC

**桶的增删改**（列表 + 按钮，双击行也能编辑）：

| 操作 | 说明 |
|---|---|
| 新增桶 | 弹出三页表单（基本 / 探测 / 续连·克隆），确定后进列表（此时只改内存） |
| 编辑 | 同上；桶标识可改，但改完要同步 `state_key` 与门户判定映射 |
| 删除 | 二次确认；至少保留一个桶；克隆桶会额外提示「判定/互顶闸一并消失」 |
| 上移 / 下移 | 只影响界面顺序（表格行、走势图配色顺序、运维总控行序） |
| 所属 | `owner` 字段：该桶账号的身份标签（如 自己 / 室友A）；账号密码页的「所属」列就取它 |
| 保存到配置 | **校验通过后**写回 `config.private.json`：先备份为 `*.bak-<时间戳>`，再原子替换 |
| 放弃改动 / 重新载入 | 丢掉内存改动，重新从文件读取 |

保存成功后会自动：重载配置 → 重建「运维总控」每桶行与走势图图例 → 刷新状态，**无需重启**。
校验会拦下：id 重复/非法、MAC 格式错误或组播地址、`probe.mode`/`renew.mode` 非法、
克隆桶缺 `clone.portal_id`、`ssh_ifup` 缺 `ssh.host`/`wan`。
（`<MAC_A>` 这类**占位符视为未填写**，不会拦住保存。）

> 写回只支持 **JSON** 配置（YAML 会丢注释，界面会提示改用 JSON 或手工编辑）。

**改 MAC**（选中桶 → 「改 MAC」，或在编辑表单的 MAC 字段）：

| 动作 | 说明 |
|---|---|
| 改配置字段 | 影响状态匹配、白名单/在线会话比对与显示；留空 = 不设 |
| 保存后立即下发 | 按 `actions.set_mac` 执行命令（会短暂断链），成功后自动回读探测一次 |

`actions.set_mac` 示例（按你的环境改，占位符：`{mac}` `{iface}` `{bucket}` `{wan}`）：

```json
"set_mac": {
  "timeout": 60,
  "confirm": "将把 {mac} 下发到 {iface}（会短暂断链）。继续？",
  "argv": ["ssh", "root@<OpenWrt管理IP>",
           "ifconfig {iface} down; ifconfig {iface} hw ether {mac}; ifconfig {iface} up"]
}
```

未配置 `set_mac` 时，「立即下发」会被禁用，只改配置字段；点「改 MAC」会给出上面这段模板提示。

## 4. 数据文件约定（生产端 → 控制台）

控制台只读 JSON。你可以用任何语言/脚本生产它，也可以直接用 `probe_buckets.py`。

### 4.1 状态文件 `app.state_file`

```json
{
  "time": "YYYY-MM-DD HH:MM:SS",
  "b_a": "ok",            // 每个桶一个键：state_key → 状态词
  "b_b": "portal",
  "aggregator": "ok",     // 聚合出口状态（可选）
  "aggregator_api": "ok"  // 控制面状态（可选）
}
```

状态词（与界面颜色/中文标签一一对应）：

| 状态词 | 界面 | 含义 |
|---|---|---|
| `ok` | 在线（绿） | 探活拿到 204，真正能上网 |
| `ok-icmp` | 在线(ICMP)（绿） | ICMP 通但未做 204 判定 |
| `portal` | 门户劫持（橙） | 流量被重定向到认证页 |
| `loss` | 丢包（红） | 探活不通 |
| `down` / `noip` | 离线 / 无IP（红/灰） | 出口不在 |
| `tundeg` | TUN退化（橙） | 直连可用但 TUN 未接管 |
| `direct` | 直连(非TUN)（蓝） | 直连成功、TUN 未在用 |
| `api-down` / `err` | API断 / 错误（红） | 控制面或探测异常 |
| `?` / `n/a` | ? / —（灰） | 未探测 / 不适用 |

### 4.2 门户文件 `app.portal_file`（可选）

```json
{
  "time": "YYYY-MM-DD HH:MM:SS",
  "tokenOk": true,
  "tokenOwner": "<账号甲>",
  "throttled": false,
  "accounts": [
    { "username": "<账号甲>",
      "online":    [ { "mac": "<MAC_A>", "ip": "<内网IP_A>", "os": "<OS>", "sid": "<会话ID>" } ],
      "whitelist": [ { "mac": "<MAC_A>", "ip": "<内网IP_A>", "os": "<OS>" } ] }
  ],
  "cloneTargets": [
    { "id": "c1", "account": "<账号乙>", "realOnline": false, "onWhitelist": true,
      "lastIP": "<内网IP_B>", "advice": "离线可续（示例）" }
  ]
}
```

- `realOnline`：`true` = 真机在线（勿动）/ `false` = 离线（可续）/ `null` = 未知（拦截）。
- `advice` 以 `no-visibility` / `no-tok` 开头时，界面显示「未知(无凭据)」。
- 文件不存在时，界面照常工作，只是相关列显示「无门户数据」。

> 门户的会话查询接口通常只返回**凭据属主自己**的会话。要让判定看清某账号的真机状态，
> 需要该账号本人的专属凭据（见 §6）。不要用凭据库里的密码去代取 —— 以他人账号登录会占用/踢掉其会话。

## 5. 生命周期：UI = 总开关

| 事件 | 行为 |
|---|---|
| 启动 | 写心跳文件（每 20s 原子刷新）+ 延迟执行 `actions.boot_chain`（幂等拉起） |
| 关闭窗口 | 最小化到托盘，**不改**生命周期 |
| 退出(全链停) | 二次确认 → 执行 `actions.stop_chain` → 撤心跳 → 退出 |
| UI 崩溃/被杀 | 心跳消失；配套任务/巡检凭心跳判定「UI 不在」而停手 |

心跳文件内容：`{"pid": <pid>, "t": <unix 秒>}`。
配套脚本建议这样门控（示意）：

```bash
# 心跳在 150s 内视为 UI 存活，否则不动作
python -c "import json,time,os,sys; p=os.environ['HB']; sys.exit(0 if os.path.exists(p) and time.time()-json.load(open(p))['t']<150 else 1)"
```

`lifecycle.on_start_remove` 用于启动时清理上次的收尾戳（例如「全链停节流戳」），避免重启后被误判。

## 6. 凭据库（账号密码页）

| 后端 | 条件 | 安全性 |
|---|---|---|
| `dpapi` | Windows | 系统按当前用户托管密钥，**无密钥文件**；换机/换用户不可解 |
| `keyring` | 已装 keyring 且有系统钥匙串 | 走 GNOME/KDE/macOS 钥匙串 |
| `file` | 以上都不可用 | 明文 base64 + `0600` 权限，**仅防误看**；界面会显著提示 |

- 录入 = 两次隐藏输入 + 确认 → 界面只显示 `*******` 并锁定（不可查看/修改/重录）。
- 更换 = 删除账号（有密文时需输入账号名二次确认）→ 重新录入。
- 明文只存在于进程内存；脚本在**真正调用接口那一刻**才 `credstore.get_secret()` 取用，勿落日志。
- 存储位置：`$BUCKET_CONSOLE_STORE` > `$BUCKET_CONSOLE_HOME/credentials.json` > `~/.bucket_console/credentials.json`。

```bash
python credstore.py backend
python credstore.py list
python credstore.py set <账号>              # 交互隐藏输入两次
echo -n '<凭据>' | python credstore.py set <账号> --stdin
python credstore.py get <账号>              # 仅此刻输出，供脚本捕获
python credstore.py remove <账号>
```

## 7. 安全边界与脱敏

- 本工具**不绕过任何付费/限速条款**，也不实现认证逻辑；请只在**你本人拥有使用权/已获授权**的账号与设备上实验。
- 仓库内的 `config.example.json` 只有占位符；真实配置请存为 `config.private.json`（已被 `.gitignore` 的 `*.private.*` 忽略）。
- 提交前请按 [docs/00_脱敏与贡献规范.md](../../docs/00_脱敏与贡献规范.md) 自查：
  真实设备标识 / 地址 / 账号 / 凭据 / 节点信息 / 本机绝对路径一律不得入库。
- 控制台会把命令原文写进事件日志（`events_file`）——**不要在命令里明文写凭据**，用凭据库或环境变量。

## 8. 常见问题

**Q：托盘图标不显示？**
缺 `pystray`/`pillow`。装上即可；不装则自动降级为纯窗口模式，底栏会提示。

**Q：卡片一直显示「聚合=未配置控制面」？**
填 `aggregation.api`（聚合出口的 REST 控制面地址）后才会做腿组探测；不填不影响其它功能。

**Q：按钮点了没反应 / 弹窗说「未配置」？**
该按钮对应的 `actions.*` 还是 `null`。用 `--check` 会列出所有未配置项与填写提示。

**Q：`门户刷新` / `真机判定` 全是「未知」？**
多为缺该账号的专属凭据。到「运维总控 → ⑤门户凭据」按账号粘贴，再点「立即重刷门户」。

**Q：Linux/macOS 上能用吗？**
能。tkinter 跨平台；计划任务区块在非 Windows 显示「不适用」（改用 `actions` 里的命令即可）；
凭据库自动选择 keyring 或文件后端；单实例用 flock。

**Q：`--selftest` 是干什么的？**
构造全部界面 + 首次刷新后立刻退出，用于改配置后快速验证不会崩，不弹窗、不起托盘。
