# 配方：单账号双桶（宽带直连 + 同账号第二桶）

> 本目录是《校园网多设备带宽合并 · 原理研究》的**最小可照做配方**。
> 与 `docs/` 里的通用原理不同，这里只讲一种最简、最安全、也只依赖**你自己一个账号**的形态：
>
> > **一条会话 = 你的宽带直连本体（直插墙口的那台设备）；另一条会话 = 用你自己账号白名单里第二台"真实离线"设备的 MAC，克隆到一台轻量软路由（如 OpenWrt）上形成的第二桶。两条会话都属于同一个账号，在出口侧合并。**
>
> 全程不涉及他人账号、不冒用他人设备；所用 MAC 均来自你账号名下、你拥有且当前离线（或未占用名额）的自有设备。本配方是"用最少材料复现多会话带宽合并"的入门路径，也是后续三桶/四桶（多账号）的起点。

---

## 1. 这个配方解决什么问题

很多校园网 / 宿舍宽带的限速是**按会话**计量的：每台在线设备（一个会话）拿到一份带宽。同一账号通常允许**一定数量的并发会话**（并发名额）。于是：

- 只要你的账号有 **≥ 2 个并发名额**，
- 且你能让**两个会话同时在线**（各自独立限速桶、独立出口），
- 就能在出口侧把两份带宽合并，得到约 **2 × 单会话上限** 的等效带宽。

本配方做的，就是把"第二个会话"稳定造出来并合并：

| 桶 | 承载 | 来源 |
|---|---|---|
| 桶 1（直连本体） | 你的电脑 / 软路由直插墙口 | 你账号的在线会话（无感免密 / 手动认证皆可） |
| 桶 2（同账号第二桶） | 一台轻量软路由上克隆的**你账号白名单里第二台离线设备**的 MAC | 你账号的第二个并发名额 |

> 为什么"只用一个账号"：这是对他人影响最小、风险最低的形态——不碰任何他人账号与设备，只在你自己已付费的套餐名额内并发，最容易自查合规边界。

## 2. 拓扑

```
                ┌────────────────────────── 你的宿主机 ─────────────────────────┐
                │                                                              │
  宿舍墙上网口 ─── 物理网线 ──┬─ 有线网卡（直连本体，桶1）── 会话1（独立限速桶）     │
                 (100M 链路)  │      直连出口 IP_A                             │
                             │                                                  │
                             ├─ VMware 桥接 ── OpenWrt 轻量 VM ──┬─ WAN（桶2）   │
                             │      克隆"你账号白名单里第二台      │   会话2（独立限速桶）
                             │      离线设备的MAC"  → 无感免密放行  │   出口 IP_B
                             │                                  └─ microsocks :1080
                             │                                                  │
                             │   聚合代理（mihomo）                            │
                             │     出站A = DIRECT（桶1，绑有线网卡）            │
                             │     出站B = SOCKS5 → OpenWrt:1080（桶2）         │
                             │     load-balance ← 所有应用流量                  │
                             └──────────────────────────────────────────────────┘
                                        TUN 虚拟网卡 = "合并出来的一台设备"
```

**要点**：
1. 限速桶按**会话**分（独立、互不共享）→ 两个会话在线 = 约 2 × 单会话带宽；
2. 你只有一根网线 = 一个本地会话；第二个会话在 OpenWrt VM 里，宿主**借道 OpenWrt 的 SOCKS** 把流量塞进桶 2；
3. 流量按**连接**分发（round-robin / L4 哈希）：多连接应用（网页、视频、多线程下载）自动吃满两桶；单条 TCP 流仍 ≤ 单会话上限（TCP 语义，不可变）；
4. 登录/会话上下文按源 IP 关联 → **必须先裸连认证好两个会话，再开 TUN**；重认证时暂停聚合。

## 3. 先看：这个配方适不适合你（前置核查）

动手前务必先确认（详见 [setup.md](setup.md) §0）：

- [ ] 你的账号有 **≥ 2 个并发名额**（查看在线设备/会话管理页，或实测能否两台设备同时在线）；
- [ ] 你账号白名单里**有第二台你拥有的、可离线/未占用名额的设备**（如闲置手机、旧电脑、虚拟机）；
- [ ] 你的接入环境允许**同账号多会话并存**（不同设备类型 / 手动认证 + 无感，往往可共存；见 setup.md §0.3）；
- [ ] 你的墙口网线物理链路 ≥ 2 × 单会话带宽（否则合不出来，见 [docs/03](../docs/03_限速机制与等效带宽.md)）。

> 若你的网络"限速按账号总量"而非按会话，或并发名额 = 1，则本配方不适用——聚合的前提本身就不成立。

## 5. 快速开始（三步）

1. **核查**：按 [setup.md](setup.md) §0 确认名额、白名单离线设备、同账号并存规则；
2. **搭第二桶**：把 OpenWrt 模板 [templates/openwrt_second_bucket.sh](templates/openwrt_second_bucket.sh) 里的占位符换成你的环境值，在 OpenWrt 上跑起来（克隆你账号第二台离线设备 MAC → 无感放行 → SOCKS → multipath）；
3. **聚合**：把 [templates/host_aggregate.yaml](templates/host_aggregate.yaml) 填好，在宿主机用聚合代理加载（先冒烟，再开 TUN）；最后按 [verify.md](verify.md) 用**并发测速**验收。

> 配置模板全部为占位符化脱敏版，替换规则见 [docs/00 脱敏与贡献规范](../docs/00_脱敏与贡献规范.md)。

## 6. 合规与边界（务必阅读）

- 本配方**只用你自己的账号与设备**：桶 2 克隆的是**你账号白名单里、你拥有且真实离线**的设备的 MAC。**绝不**克隆他人设备的 MAC，也**不**使用他人账号。
- 多会话并发可能超出套餐的单设备限速条款，存在账号风控风险（被检测到多设备并发超带宽），**风险自担**；
- 遵守你所在网络 / 运营商的用户协议与当地法规；本配方仅用于技术学习与**在你有使用权的设备/账号**上实验；
- 本配方只是"维持已在线会话"，**不提供**接入真实网络的服务，也不对任何真实环境复用负责；
- 详细脱敏红线、占位符规范与提交自查见 [docs/00](../docs/00_脱敏与贡献规范.md)。
